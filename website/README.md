# Website Notes

This folder tracks the user's 3D model and painting website as a business/marketing asset.

The actual website code should likely stay in a separate repository, especially if it is HTML/CSS/JS and deployed through Netlify.

This folder is for planning, strategy, content, and integration notes related to the website.

## Current context

The user has been working on a website for:

- 3D models
- painted models
- showcasing products
- possibly supporting the Vieux Pepe / Vieux Pépé brand

The website is made with HTML and posted online through Netlify.

The user plans to send the full project files later so the AI can inspect the site structure, content, and possible improvements.

## Recommendation

Keep the website code in its own separate repository.

Reason:

- The website is a code project.
- This repo is a planning and business memory system.
- Separating the code prevents the planning repo from becoming messy.
- The business repo can still track website strategy, content needs, product links, and SEO notes.

## How this repo should connect to the website

Use this folder to track:

- website goals
- product pages to add
- homepage messaging
- SEO ideas
- portfolio/gallery structure
- MakerWorld/Cults3D links
- painting showcase ideas
- product descriptions reused from `product-catalog/`
- content updates needed after new model releases

## Suggested workflow

1. Product is planned in `product-catalog/`.
2. Product is released on MakerWorld or Cults3D.
3. Website gets updated with a product showcase page or gallery entry.
4. Website notes are recorded here.
5. Market observations from website performance can be added to `market-research/`.
